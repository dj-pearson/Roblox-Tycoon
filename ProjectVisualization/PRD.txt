# Gym Tycoon PRD - Building Your Ultimate Fitness Empire

## 1. Project Overview

### Purpose
Create an engaging tycoon game where players build and manage their own fitness center, focusing on both physical expansion and membership growth.

### Core Gameplay Loop
1. Purchase tiles to unlock gym equipment and areas
2. Maintain equipment and keep members happy
3. Complete challenges and mini-games for rewards
4. Grow membership base to earn more revenue
5. Expand to additional floors and outdoor areas

## 4. Model Attribute Standards

All models in ServerStorage should follow this attribute standard:

1. **Common Attributes for All Models**:
   - `ID` (number): Unique identifier for the model
   - `Name` (string): Display name for the model
   - `Floor` (number): Floor number (1, 2, 3, or 0 for outdoor)
   - `FloorName` (string): Name of the floor (e.g., "Cardio Area", "Weights Section")
   - `ModelType` (string): Type of model (Equipment, Decoration, Service, etc.)

2. **Equipment-Specific Attributes**:
   - `EquipmentType` (string): Type of equipment (Cardio, Strength, etc.)
   - `BaseCost` (number): Base purchase cost
   - `CleaningReward` (number): Cash reward for cleaning
   - `MembershipImpact` (number): Impact on membership numbers when added
   - `MaintenanceInterval` (number): How quickly it gets dirty (in seconds)
   - `XPReward` (number): XP gained when player interacts with it

3. **Service-Specific Attributes** (Front Desk, Juice Bar, etc.):
   - `ServiceType` (string): Type of service
   - `RevenueBoost` (number): How much it boosts gym revenue
   - `StaffRequired` (boolean): Whether it requires staff to operate

## Script Implementation Examples

### Enhanced TileSystem (Based on BuyTileSystem)

```lua
-- TileSystem.lua (Enhancement of existing BuyTileSystem)
local TileSystem = {}
TileSystem.initialized = false

-- Configuration
local CONFIG = {
    SAVE_KEY = "ownedTiles",
    DEFAULT_COST_MULTIPLIER = 1.0,
    PROGRESSION_MULTIPLIER = 1.2,
    COST_ROUND_TO = 10,
    MAX_TILES_PER_TYCOON = 100,
    FLOOR_PROGRESSION = {
        [2] = 0.7, -- Need 70% of floor 1 to unlock floor 2
        [3] = 0.7, -- Need 70% of floor 2 to unlock floor 3
        [4] = 0.5  -- Need 50% of floor 3 to unlock outdoor (floor 4)
    }
}

-- Internal state
local tiles = {}
local playerTiles = {}
local floorTiles = {[1] = {}, [2] = {}, [3] = {}, [4] = {}} -- Outdoor is floor 4

-- Spawn a model based on tile information
function TileSystem.spawnModel(player, tileId)
    local tile = tiles[tileId]
    if not tile or not tile.modelId then return end
    
    -- Find model in ServerStorage
    local ServerStorage = game:GetService("ServerStorage")
    local model = ServerStorage:FindFirstChild("GymModels"):FindFirstChild(tostring(tile.modelId))
    if not model then
        warn("[TileSystem] Model not found for ID: " .. tile.modelId)
        return
    end
    
    -- Clone and position model
    local clone = model:Clone()
    clone.Parent = workspace.PlayerTycoons[player.Name]
    clone:SetPrimaryPartCFrame(CFrame.new(tile.position))
    
    -- Process model attributes
    local modelType = model:GetAttribute("ModelType")
    if modelType == "Equipment" then
        TileSystem.getSystem("EquipmentSystem").registerEquipment(clone)
    elseif modelType == "Service" then
        local serviceType = model:GetAttribute("ServiceType")
        TileSystem.getSystem("MembershipSystem").updateFromService(player, serviceType)
    end
    
    -- Apply membership impact
    local membershipImpact = model:GetAttribute("MembershipImpact") or 0
    if membershipImpact > 0 then
        TileSystem.getSystem("MembershipSystem").updateMemberCount(player, membershipImpact)
    end
    
    return clone
end

-- Check if a floor is unlocked for a player
function TileSystem.isFloorUnlocked(player, floorNumber)
    if floorNumber == 1 then return true end -- Floor 1 always unlocked
    
    local previousFloor = floorNumber - 1
    local ownedOnPreviousFloor = 0
    local totalOnPreviousFloor = #floorTiles[previousFloor]
    
    -- Count owned tiles on previous floor
    for _, tileId in ipairs(floorTiles[previousFloor]) do
        if TileSystem.isTileOwned(player, tileId) then
            ownedOnPreviousFloor = ownedOnPreviousFloor + 1
        end
    end
    
    local progressionThreshold = CONFIG.FLOOR_PROGRESSION[floorNumber] or 0.7
    return (ownedOnPreviousFloor / totalOnPreviousFloor) >= progressionThreshold
end

-- Get available tiles for a player by floor
function TileSystem.getAvailableTilesByFloor(player, floorNumber)
    if not TileSystem.isFloorUnlocked(player, floorNumber) then
        return {}
    end
    
    local availableTiles = {}
    
    -- Check each tile on this floor
    for _, tileId in ipairs(floorTiles[floorNumber]) do
        if not TileSystem.isTileOwned(player, tileId) then
            -- Check prerequisites
            local meetsPrerequisites = true
            local tile = tiles[tileId]
            
            if tile.requiredTiles then
                for _, requiredTileId in ipairs(tile.requiredTiles) do
                    if not TileSystem.isTileOwned(player, requiredTileId) then
                        meetsPrerequisites = false
                        break
                    end
                end
            end
            
            if meetsPrerequisites then
                table.insert(availableTiles, tileId)
            end
        end
    end
    
    return availableTiles
end

-- Get a system from CoreRegistry
function TileSystem.getSystem(systemName)
    local CoreRegistry = TileSystem.getCoreRegistry()
    return CoreRegistry and CoreRegistry:getSystem(systemName)
end

-- ...existing code...

return TileSystem
```

## 12. Detailed Attribute System

All gym objects use an attribute-based system for identification and categorization:

### Floor Attributes
- `Floor`: Numeric value (1-6) representing the floor number
- `FloorName`: String ("1st", "2nd", etc.) for display in UI elements
- These attributes are automatically applied based on the parent folder

### Room Attributes
- `Room`: String identifying which room the object belongs to
- Objects inherit this attribute from their parent room folder

### Category Attributes
- `Category`: Equipment category (Structure, Cardio, Strength, etc.)
- Used for organizing purchases and gameplay progression

### Placement Attributes
- `NeedsWall`: Boolean indicating if equipment must be placed against a wall
- `IsCorner`: Boolean indicating if item should be placed in corner areas
- `ClearanceRequired`: Number indicating space needed around equipment

## 13. Floor Progression System

The BuyTileSystem enforces floor-based progression:

### Sequential Floor Unlocking
- Floors are unlocked in sequence (1st → 2nd → 3rd → 4th → Roof → Outside)
- Each floor requires completion of key elements on the previous floor
- Stairs or elevators act as gateway purchases between floors

### Floor Completion Requirements
- Every floor has "required" purchases before it's considered complete
- Required items are tagged with `isRequired = true` in BuyTileSystem
- Structure elements (walls, floor) always come first in the build order

### Room-Based Organization
- Rooms on each floor follow a logical unlock sequence
- Entrance → Main Areas → Specialized Areas → Amenities
- Room completion triggers events for game progression

## 14. Build Order Logic

The progression system uses a build order to determine purchase sequence:

- `buildOrder` property determines sequence within each floor
- Lower numbers must be built before higher numbers
- Structure (1-100) → Basic Equipment (101-200) → Advanced (201+)

### Prerequisites System
- Each item can have prerequisites that must be purchased first
- Prerequisites can be specific items or completion of an entire floor
- Prerequisites are defined both in code and through model attributes

### Floor Gating
- Higher floors require "gateway" purchases (stairs, elevators)
- Gateway items set the `unlocksFloor` attribute to the next floor
- Each floor has a minimum set of required items before gateway unlocks
